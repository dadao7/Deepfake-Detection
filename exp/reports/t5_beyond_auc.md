## 1. 위치(설명) 지표 — 가장 큰 "AUC 밖" 가치

### 1.1 무엇을 쟀나
- FF++ 공식 조작 마스크를 h5 얼굴 crop에 정렬했다(SIFT + RANSAC, 정렬 품질 NCC ≥ 0.95 통과 프레임만, test 5,472프레임).
- heatmap(11×11)이 실제 조작 위치를 가리키는지 6가지 지표로 쟀다.

| 지표 | 정의 | 쉬운 말 |
|---|---|---|
| 경계 적중률 | heatmap 최댓값 셀이 조작 경계(셀 안 조작 비율 10~90%)에 있는 비율 | "가장 의심스럽다고 찍은 곳이 합성 경계인가" |
| 경계 셀 AUROC | 경계 셀과 나머지 셀을 heatmap 값으로 구분하는 능력(50 = 무작위) | "경계를 얼마나 잘 골라내나" |
| 영역 셀 AUROC·IoU·최댓값 적중 | 조작 영역 안쪽(비율 ≥ 50%) 기준 | "조작된 면적을 덮나" |
| top-3 crop 적중률 | 분류에 쓰는 64×64 crop 3개 중 하나라도 조작 픽셀 ≥ 50% | "분기가 실제로 조작 부위를 보나" |

### 1.2 왜 경계 지표를 봐야 하나 (정직한 해석)
- FF++ 마스크는 얼굴 crop의 42~54%를 가운데에 덮는다. 그래서 **얼굴 중앙만 찍는 지도**가 영역 셀 AUROC 93.6, 최댓값 적중 99.3%, crop 적중 99%로 안쪽 지표에서 1위다.
- 따라서 안쪽 지표로 "우리 heatmap이 위치를 잘 찾는다"고 말하면 안 된다. 조작을 찾는 능력은 **경계 지표**로 판단한다. 경계 지표에서 중앙 지도는 무작위 수준이다(경계 적중 0%, 경계 AUROC 47.7).
- SBI 사전학습 heatmap은 원래 "합성 경계(블렌딩 경계)"를 찾도록 학습됐으므로, 경계 지표가 목적에 맞는 지표이기도 하다.

### 1.3 결과

| heatmap | 경계 적중 | 경계 AUROC | top-3 crop 적중 |
|---|---|---|---|
| 얼굴 중앙 고정 지도 | 0% | 47.7 (무작위) | 99%(안쪽 포화) |
| SBI 경계 탐지기(seg head) | 35.3% | 70.8 | 96.9% |
| **P3 분류 heatmap (detach 유지)** | **35.6±0.1%** | **70.5** | 96.6% |
| P4a (detach 제거) | 4.8±2.0% | 56.1 | 98.0% |
| anchor λ=100 (detach 제거 + 고정점 정규화) | 37.4±0.4% | 70.8 | 97.2% |

- **P3의 heatmap은 조작 경계를 무작위보다 확실히 잘 찾는다.** 가장 의심스러운 셀 3개 중 1개꼴(35.6%)로 합성 경계에 있다. 중앙 지도는 한 번도 경계를 찍지 않는다.
- 이 능력은 SBI 사전학습에서 오고, **detach가 그 능력을 지킨다.** detach를 빼면(P4a) 분류 손실이 heatmap을 얼굴 중앙으로 끌어당겨 경계 적중이 4.8%로 무너진다. SBI로 학습해도 같은 붕괴가 나온다(8.7%).
- 그래서 발표에서는 "위치 정확도를 **올렸다**"가 아니라 "**분류 성능을 유지하면서 위치 설명 능력을 잃지 않는 구조를 찾았다**"고 말하는 것이 정확하다. 위치를 학습하게 둔 구조(P4a)는 이 능력을 잃는다.

### 1.4 위치와 일반화가 같이 움직인다 (인과 증거)
- detach를 빼되 heatmap을 seg head 쪽으로 붙잡는 정규화(anchor)를 강도별로 학습했다. 다른 조건은 모두 같다.
- 강도를 올릴수록 경계 적중(5.0 → 14.9 → 37.4%)과 Celeb-DF AUC(69.3 → 74.8 → 76.5), DFD AUC(66.6 → 68.3 → 70.3)가 **함께 회복된다**(`t4_fig_anchor.png`).
- 의미: P4a의 교차 데이터셋 손해는 "gradient가 흘러서"가 아니라 "heatmap 위치가 무너져서" 생긴다. 위치 설명은 장식이 아니라 **일반화 성능의 조건**이다. 논문의 핵심 주장 중 하나로 쓸 수 있다.

## 2. 과적합 저항 — "언제 멈춰도 안전한 모델"

| 설정 | val 손실 상승폭(last − 최저) | Celeb-DF AUC best → last |
|---|---|---|
| P1 | 0.11 | 75.57 → 73.41 (−2.2) |
| P2 (고정 결합 α = 0.5) | 0.37 | 76.28 → 69.15 (**−7.1**) |
| **P3 (동적 결합 + 패치 정규화)** | **0.10** | 76.86 → 76.24 (**−0.6**) |
| P4a (detach 제거) | 0.71 | 70.44 → 69.07 |

- P2는 오래 학습하면 detail 분기가 학습 데이터를 외워(학습 손실 0.03) Celeb-DF 판정의 약 절반을 뒤집는다.
- P3는 동적 결합의 가중치 α가 학습할수록 baseline 쪽으로 커져(0.68 → 0.90) 과적합된 분기의 몫을 스스로 줄인다. 그래서 last에서도 무너지지 않는다.
- 같은 현상이 SBI로 학습할 때도 재현됐다(P2 → P3: FF++ +2.1, Celeb-DF +7.3, bACC +8.45, 2SD 기준 충족).
- 실무 의미: 검증 세트로 epoch를 고르기 어려운 상황(새 도메인, 라벨 부족)에서도 마지막 모델을 그대로 써도 된다.

## 4. 오탐·미탐 균형 — 정확도 한 숫자가 가리는 것

### 4.1 왜 ACC 하나로는 부족한가
- 보고 세트의 진짜:가짜 비율은 FF++ test 1:4, DFD-test 1:5.7, Celeb-DF 1:1.9다. **모든 영상을 "가짜"라고 답하기만 해도** ACC가 FF++ 80%, DFD 85%가 된다.
- 그래서 불균형 세트에서는 **균형 정확도 bACC = (진짜 정답률 + 가짜 정답률)/2**와 오탐률·미탐률을 함께 봐야 한다. FaceShifter(1:1)는 ACC와 bACC가 같다.

### 4.2 결과 (기준값 0.5)

| 모델 | FF++ 오탐 / 미탐 / bACC | Celeb-DF | FaceShifter | DFD-test |
|---|---|---|---|---|
| P0 | 27.1 / 4.5 / 84.2 | 7.3 / 67.6 / 62.5 | 26.4 / 42.1 / 65.7 | 54.6 / 19.4 / 63.0 |
| P3 | 25.7 / 5.4 / 84.5 | 6.6 / 70.1 / 61.7 | 25.5 / 44.0 / 65.2 | 54.6 / 19.8 / 62.8 |
| 모델 2개 결합(같은 seed P3×0.3 + U3s×0.7) | **15.5** / 10.8 / **86.8** | 7.5 / 63.6 / **64.4** | **16.4** / 51.2 / **66.2** | **23.2** / 39.7 / **68.6** |
| **task vector 병합(단일 모델)** | **14.0** / 13.3 / **86.3** | **2.6** / 74.7 / 61.3 | **14.5** / 58.8 / 63.3 | **19.9** / 42.5 / **68.8** |

- SBI 전문가가 들어간 모델(결합·병합)은 **진짜 영상을 가짜로 모는 오탐을 크게 줄인다**. 병합 단일 모델 기준으로 FF++ 25.7 → 14.0%, DFD 54.6 → 19.9%다. 딥페이크 탐지 앱에서는 무고한 영상을 가짜로 판정하는 오류가 특히 비싸다.
- 대가로 기준값 0.5에서는 미탐(가짜를 놓침)이 늘어난다. 병합 모델은 선택 세트로 보정한 기준값(0.35~0.52)을 쓰는 것이 맞다(`t5_final.md` §3.2).
- bACC 짝 비교(기준값 0.5)
  - 모델 2개 결합 − P3: Celeb-DF **+2.77 ✔**, DFD-test **+5.79 ✔**, FF++ +2.38, FaceShifter +0.95(불분명)
  - 병합 − P3: DFD-test **+6.00 ✔**, FF++ +1.88, Celeb-DF −0.34, FaceShifter −1.90(불분명)
- 남은 약점: Celeb-DF 미탐률이 여전히 60%대다. 모든 모델이 Celeb-DF 가짜를 "진짜 쪽"으로 점수 매긴다.

### 4.3 기준값만 옮겨서는 못 고친다 (M2 음성 결과)
- 선택 세트(FF++ val·DFD-val)에서 bACC가 가장 높은 기준값을 고르면 P3의 기준값이 0.63~0.82로 올라간다. DFD는 오탐이 많아서 기준값을 올리라고 하기 때문이다.
- 그런데 Celeb-DF는 미탐이 많아서 반대로 내려야 한다. 그 결과 Celeb-DF ACC가 51.7 → 40.5로 떨어졌다(`t5_calib.md`).
- 의미: 도메인마다 점수가 어긋나는 **방향이 반대**다. 그래서 "기준값 하나 보정"으로는 해결되지 않는다. 이것이 AUC(기준값과 무관)를 주 지표로 쓰는 근거이고, 실사용에서는 도메인별 보정이 필요하다는 근거다.

- P3 단독의 +0.82는 작지만 CI가 0 밖인 유일한 단일 설정 향상이다. 병합 단일 모델은 P3보다 +4.1 높다(✔).

## 6. 발표에서 이렇게 말하면 정확하다
1. "우리 구조는 판정 근거(조작 경계 위치)를 무작위보다 확실히 잘 짚고(경계 적중 35.6% vs 0%), 이 능력을 지키는 것이 처음 보는 데이터 성능을 지키는 조건임을 통제 실험으로 보였다."
2. "동적 결합은 과적합 안전장치다. 오래 학습해도 Celeb-DF가 0.6만 떨어진다(고정 결합은 7.1). 두 가지 다른 학습 데이터에서 같은 효과가 재현됐다."
3. "seed를 바꿔도 결과 차이가 0.12로, 비교한 구조 중 가장 재현성이 높다."
4. "두 데이터 전문가를 가중치 병합한 단일 모델은 진짜 영상 오탐을 FF++에서 46%, DFD에서 64% 줄이고(25.7→14.0%, 54.6→19.9%), DFD 균형 정확도를 6%p 올린다."

하지 말아야 할 말: "위치 정확도 99%"(중앙 찍기도 99%), "ACC 85% 달성"(DFD에서 전부 가짜라고 해도 85%).

## 7. 병합 모델(TASKS5)의 AUC 외 지표

| 지표 | P3 | task vector 병합 | 수프(lin) | 증류(last) | 의미 |
|---|---|---|---|---|---|
| 경계 적중 / 경계 AUROC | 35.6% / 70.5 | 35.1% / 70.7 | 35.3% / 70.7 | 35.3% / 70.6 | 위치 설명 능력 유지 |
| top-3 crop 적중 | 96.6% | 96.7% | 96.7% | 96.6% | 분기가 여전히 조작 부위를 본다 |
| 오탐률 FF++ / DFD (0.5) | 25.7 / 54.6% | **14.0 / 19.9%** | **12.1 / 12.1%** | 11.4 / 17.0% | 진짜 영상을 가짜로 모는 오류가 크게 줄어든다 |
| 미탐률 FF++ / Celeb-DF (0.5) | 5.4 / 70.1% | 13.3 / 74.7% | 15.0 / 74.4% | 15.1 / 70.9% | 대신 놓치는 가짜가 늘어난다 → 보정 기준값 필요 |
| seed 안정성(AUC 표준편차 평균) | **0.12** | 0.56 | (단일 모델) | 0.70 | SBI 전문가(1.44)보다 훨씬 안정, P3보다는 덜 안정 |
| 추론 비용 | 1 | 1 | 1 | 1 | 모델 2개 결합(비용 2)과 같은 성능을 비용 1로 |

- heatmap head는 detach로 분류 손실을 받지 않으므로(P3·U3s 모두 같은 SBI 사전학습 head, BN 통계만 다름), 병합해도 위치 지도가 거의 바뀌지 않는다. **분류 성능을 올리면서 설명 능력은 그대로 유지하는 개선**이다.
- 오탐·미탐 균형이 P3와 다르게 움직인다는 점이 실사용에서 중요하다. 기준값을 0.5로 두면 진짜 쪽 판정이 많아진다. 선택 세트로 고른 기준값(병합 0.35~0.52)을 함께 써야 bACC·ACC가 모두 오른다(`t5_final.md` §3.2).
